# Theta* — any-angle pathfinding для врагов

Дата: 2026-06-05. Статус: дизайн утверждён, ждёт реализации.

## Проблема

Враги ходят неэффективными маршрутами с изломами «вбок» даже в открытом
поле (без препятствий между врагом и целью). Три причины:

1. **Квантование старта.** `reconstructPath` отбрасывает стартовую клетку,
   а `smoothPath` безусловно сохраняет `waypoints[0]` — центр клетки
   сетки 64×64. Враг при каждом пересчёте сначала идёт к центру клетки,
   смещённому до ~45 px вбок от прямой на цель.
2. **Устаревший путь.** Пересчёт только при смещении цели больше
   `PATH_RECALC_DIST` (128 px = 2 клетки) — враг ходит к прошлым
   позициям игрока.
3. **Лесенки A\*.** Эвристика Чебышёва при стоимостях 1/√2 не различает
   равностоимостные пути — выбирается произвольная «лесенка», которую
   string pulling прячет лишь частично.

Дополнительно: debug-оверлей (F1) рисует путь от врага через **все**
вейпоинты с нулевого, игнорируя `waypointIndex`, — показывает уже
пройденные точки и искажает картину при диагностике.

## Решение

Заменить A\* + string pulling на **Theta\*** (basic) — any-angle вариант
A\*: при раскрытии соседа проверяется grid-LoS от `parent(current)` до
соседа; при видимости сосед наследует родителя «через голову» current
с евклидовой стоимостью. Путь получается натянутым по построению.

### Изменения в `src/ai/Pathfinder.ts`

1. `astar()` → `thetaStar()`:
   - стоимости и эвристика — евклидовы (вместо Чебышёва и 1/√2);
   - при экспансии соседа: если `gridLoS(parent(current), neighbor)` —
     `g = g(parent) + dist(parent, neighbor)`, `parent(neighbor) = parent(current)`;
     иначе обычный шаг A\*;
   - существующий `gridLoS` переиспользуется без изменений (защита от
     срезания углов в нём уже есть).
2. **LoS-шорткат** в начале `findPath`: если `gridLoS(from, to)` чистый —
   вернуть `[точная цель]` без поиска. Покрывает основной кейс
   (открытое поле) за один DDA-проход.
3. **Трим старта** после поиска: отбрасывать ведущие вейпоинты, пока от
   реальной позиции врага есть grid-LoS до следующего за ними. Лечит
   квантование старта, которое Theta\* сам не убирает.
4. Удалить `smoothPath` и флаг `PATH_SMOOTH_ENABLED` (`config.ts`) —
   string pulling становится мёртвым кодом.
5. Последний вейпоинт по-прежнему заменяется точной целью; обработка
   заблокированных старта/цели (`nearestWalkable`) не меняется.

### Сопутствующие изменения

- `PATH_RECALC_DIST`: 128 → 64 (`config.ts`). Пересчёт чаще, но в
  большинстве случаев это один LoS-шорткат — дёшево.
- Debug-оверлей: в `Enemy` метод `getWaypoints()` заменяется на
  `getRemainingWaypoints(): Vector2[]` (срез с текущего `waypointIndex`);
  `GameScene.drawDebugPaths` переходит на него.

### Что НЕ меняется

- Интерфейс `findPath(fromX, fromY, toX, toY): Vector2[]` и контракт
  с `Enemy.moveAlongPath` (включая stuck-recovery и wall separation).
- Сетка 64×64, `MeleeEnemy`/`ShooterEnemy`.

> Обновление 2026-06-05: инфляция стен на 32 px убрана — для выровненных
> по сетке стен она блокировала целиком соседние проходимые тайлы, и на
> маленьких картах не оставалось места. Блокируются только клетки самих
> стен (полуоткрытый интервал по границе тайла). Клиренс обеспечивают
> corner-cutting-проверки Theta*/gridLoS, wall separation force и
> физический коллайдер врагов со стенами.

## Производительность

Сетка ~30×17 ≈ 510 клеток; LoS — DDA по ≤30 клеток. Theta\* делает
один LoS на экспансию — при 6 врагах и пересчётах раз в 64 px смещения
цели нагрузка пренебрежимо мала. Линейный поиск минимума в open list
сохраняется (бинарная куча не нужна на таком размере).

## Верификация (ручная, `make dev` + F1)

1. Открытое поле: путь — одна прямая линия от врага до цели, без изломов.
2. Цель за кустом: натянутая ломаная, огибающая угол вплотную, без лесенок.
3. Враг не дёргается вбок в момент пересчёта пути.
4. Узкий проход (1 клетка): враг проходит, не цепляясь за углы
   (corner-cutting защита).
5. Оверлей показывает только оставшийся путь.
6. `make typecheck && make check && make build` — чисто.
