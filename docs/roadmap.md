# Top-Down Shooter — роадмап

Текущее состояние проекта (архитектура, баланс, что реализовано): [`docs/spec.md`](spec.md).

## Уже реализовано

- M1–M2: скелет проекта, игрок, движение, стены
- M3: стрельба, пистолет
- M4: melee-враги (state machine, dodge, slot-based positioning, pack alerts, pathfinding)
- M5: shooter-враги (LoS, SEARCH, кайтинг, dodge с LoS-гейтом)

## Оставшиеся вехи

Каждая веха — отдельный коммит/PR, заканчивается рабочим билдом в браузере.

### M6. Дробовик и переключение оружий

- `Shotgun.ts`: N пуль с разбросом ±15°, кулдаун 700 мс.
- Переключение: клавиши 1/2 или колесо мыши.
- Ограниченные патроны на каждое оружие; расход при выстреле. Стартовый запас: пистолет 60, дробовик 20 выстрелов.
- **Verify:** обе пушки работают, переключение работает, патроны тратятся.

### M7. Пикапы

- `Pickup.ts` с типами `health`, `ammo_pistol`, `ammo_shotgun`.
- Overlap с игроком → применить эффект (аптечка +2 HP, ящики — заданное количество патронов) → удалить.
- Расставить пикапы в `level/level1.ts` (поле `pickups` уже зарезервировано в формате уровня).
- Коллизия pickup↔стены не нужна (статичные объекты).
- **Verify:** пикапы подбираются, эффект применяется, спрайт исчезает.

### M8. UI и состояния

- `MainMenuScene`: стартовый экран с кнопкой «Начать».
- `HUDScene` (оверлей поверх GameScene): HP, патроны текущего оружия, счётчик оставшихся врагов. Коммуникация через `scene.events.emit()` из GameScene.
- Кнопка «Заново» в GameOverScene должна перезапускать без обновления страницы.
- DebugOverlay скрывать в продакшн-билде (или убрать из финальной версии).
- **Verify:** полная петля Меню → Выбор уровня → Игра → GameOver → Меню работает без перезагрузки.

### M9. Полировка

- Балансировка чисел в `config.ts` по ощущениям от игры.
- Расширить `level/level1.ts` при необходимости (больше врагов, интереснее карта).
- **Verify:** игра ощущается играбельно, баланс нормальный.

### M10. Умный бот (SmartBot)

Осознанное **расширение скоупа** относительно исходного прототипа: соперник уровня игрока с
продвинутым ИИ в духе Quake 3. Реализовано (см. `docs/spec.md` → раздел «Враги», `SmartBot`).

- `SmartBot.ts`: HP/скорость/оружие как у игрока; упреждающий прицел с моделью точности и реакции,
  уклонение от пуль, тактика укрытий при низком HP, боевое маневрирование (circle-strafe).
- Патрулирование карты (роуминг по случайным проходимым точкам) и активный поиск: после потери
  игрока бот идёт к последней позиции, обыскивает район, затем возвращается к патрулированию.
- Спавн через объект `smart` в Tiled-слое `spawns` (тестовый — на карте `level3`).
- Все числа в `config.ts` (блок `SMART_BOT_*`).
- **Verify:** бот замечает игрока и идёт в бой; пули летят с упреждением (не точно в текущую точку
  при стрейфе); видна задержка реакции; бот уклоняется вбок от пуль; кружит вокруг и держит
  дистанцию; на низком HP уходит за стену и возвращается; умирает от пуль игрока; после смерти всех
  врагов — экран WIN. Подкрутить `SMART_BOT_AIM_SPREAD`/`REACTION_MS` под ощущение «честно, но сложно».

## Что не входит в прототип

- Сохранения, прогрессия между запусками.
- Звук.
- Несколько уровней с различным дизайном.
- Анимации спрайтов (используем статичные Kenney).
- Мобильное управление, геймпады.
