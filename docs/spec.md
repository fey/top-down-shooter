# Top-Down Shooter — спецификация (текущее состояние)

Браузерный прототип top-down шутера: статичные уровни из Tiled, три типа врагов, четыре оружия (пистолет, дробовик, винтовка, автомат). Этот документ описывает **то, что реализовано сейчас**. Оставшаяся работа — в [`docs/roadmap.md`](roadmap.md).

## Стек

- **Phaser 4** — 2D-движок (точные версии стека — в `CLAUDE.md`).
- **TypeScript** в строгом режиме (`strict: true`).
- **Vite** — dev-сервер и сборка.
- **Biome** — линт и форматирование (вместо ESLint + Prettier), единый `biome.json`.

## Команды

```bash
make install    # npm ci
make dev        # Vite dev server

```

## Тестируемость

Ошибкоопасная логика вынесена в чистые Phaser-free модули и покрыта
unit-тестами vitest. Классы-сущности — тонкая оболочка над этим ядром; геймплей проверяется
вручную (ручной **Verify**, см. чеклисты вех в `roadmap.md`).

| Модуль | Что покрыто тестом |
|--------|--------------------|
| `src/ai/grid.ts` | поиск пути (Theta*), сеточный LoS, ближайшая и случайная проходимая точка |
| `src/ai/geometry.ts` | геометрия LoS: пересечение отрезка со стенами |
| `src/ai/separation.ts` | отталкивание от стен (`wallSeparationForce`) |
| `src/ai/behaviors/navigation.ts` | восстановление при застревании: пропустить вейпоинт → пересчитать путь |
| `src/ai/behaviors/combat.ts` | кайтинг, упреждение прицела, решение об уклонении |
| `src/ai/behaviors/alert.ts` | агро от чужой стрельбы: откуда прилетела просвистевшая пуля |
| `src/weapons/Weapon.ts` | выстрел целиком: темп, неточность, веер, урон и скорость каждой пули |
| `src/weapons/pellets.ts` | веер дробинок (внутренняя деталь `Weapon`) |
| `src/level/spawns.ts` | парсинг слоя `spawns` |
| `src/ui/hud.ts` | форматирование строк HUD |
| `src/config.ts` | инварианты баланса (`config.test.ts`) |

## Архитектура

### Поток сцен

```
Boot → Preload → MainMenu → LevelSelect → Game (+ HUD) → GameOver ⇄ MainMenu
```

Петля замкнута: из GameOver можно перезапустить тот же уровень или вернуться в меню, не
перезагружая страницу.

- **BootScene** — точка входа, немедленно запускает PreloadScene.
- **PreloadScene** — грузит тайлсет и карты, остальные текстуры генерирует процедурно (`Graphics` и `DynamicTexture`, спрайты сущностей из файлов не загружаются). После завершения — MainMenuScene.
- **MainMenuScene** — стартовый экран: кнопка «Начать» (или Enter/Space) → LevelSelect, справка по управлению.
- **LevelSelectScene** — меню по реестру `level/levels.ts` (сейчас три уровня): клик по строке или цифра 1–9; ESC → MainMenu.
- **GameScene** — главная сцена. Загружает Tiled-карту через `LevelLoader`, создаёт игрока, врагов, пикапы, управляет коллизиями. ESC → LevelSelect, F1 → debug path overlay (только в dev-сборке). Запускает HUDScene параллельно (`scene.launch`) и гасит её на своём `shutdown`.
- **HUDScene** — оверлей поверх боя: HP (краснеет на `HUD_HP_LOW` и ниже), название текущего оружия, счётчик живых врагов. Своя камера, которая не следует за игроком, поэтому надписям не нужен `setScrollFactor(0)`. Экземпляр `GameScene` не получает: эмиттер событий и начальный снимок приходят данными `scene.launch`. Форматирование строк — в чистом `ui/hud.ts` (зажим отрицательного HP, цвет по порогу) с unit-тестами.
- **GameOverScene** — экран WIN/LOSE. Получает от `GameScene` исход и конфиг уровня, поэтому «Заново» (кнопка или R) перезапускает тот же уровень, а «В меню» (кнопка или ESC) возвращает в MainMenu — без перезагрузки страницы.
- **DebugOverlay** — не сцена, а оверлей внутри `GameScene`; создаётся только при `import.meta.env.DEV`, в продакшн-сборку не попадает вовсе (ветка вырезается вместе с классом). Под тем же гейтом и F1-отладка навигации: в релизе сетка не рисуется и клавиша не слушается.

### Символьный рендер

Спрайты не грузятся из файлов: `PreloadScene` генерирует все текстуры сущностей процедурно
(`Graphics` → `generateTexture`). Сущность = круг тела радиусом `*_BODY_RADIUS` цвета из палитры
+ ствол-индикатор вдоль +X (`rotation = 0` ⇒ восток), который показывает направление прицела.
Круг всегда в центре текстуры, поэтому `origin (0.5, 0.5)` совпадает с осью вращения и с круговым
телом `setCircle`. Так снят потолок «сколько нарисовано спрайтов» — новое оружие или тип врага
добавляется числами в `config.ts`, а не файлом арта.

Важное следствие: **размер текстуры зависит от длины ствола**, поэтому после смены текстуры тело
надо пересчитывать (`Player.equip` → `syncBody`).

### Игрок (`Player`)

Sprite + Arcade Physics body. Управление: WASD (нормализованный вектор), мышь — прицеливание,
ЛКМ — стрельба. Хранит HP, текущий `WeaponDef` и экземпляр `Weapon`. Стартует с пистолетом;
`equip(def)` меняет дескриптор, оружие, текстуру (`player_<id>`) и пересчитывает тело. Пули
вылетают из центра игрока (а не с конца ствола) — иначе выстрел в упор к стене спавнил бы пулю
внутри стены. При смерти эмитирует событие в GameScene.

### Оружие (`Weapon` + реестр `WEAPONS`)

Оружие — **данные, а не подклассы**: `WEAPONS` в `config.ts` хранит `WeaponDef`
(`name`, `glyph`, `cooldown`, `bulletSpeed`, `damage`, `pelletCount`, `spreadRad`, `aimSpreadRad`,
`barrel`), а единственный класс `Weapon` его исполняет. `name` — человекочитаемое имя, которое
показывает HUD; его уникальность и непустота проверяются инвариантом в `config.test.ts`. Добавить пушку = добавить запись в
реестр: текстура игрока и текстура пикапа генерируются из `barrel` и `glyph` автоматически.

- `Weapon` **Phaser-free**: `tryFire(x, y, angle, now)` возвращает `BulletSpec[]` — по одной
  спецификации (`x`, `y`, `angle`, `speed`, `damage`) на дробинку. Пустой массив означает, что
  темп не пустил; отдельного признака «не выстрелил» нет. Окно темпа сдвигает только
  состоявшийся выстрел, поэтому зажатая кнопка не заставляет оружие замолчать.
- Пули в мир кладёт адаптер `spawnBullets(group, specs)` (`entities/Bullet.ts`) — единственное
  место, где выстрел становится объектами сцены. Его зовут `Player.update` и `SmartBot`;
  `ShooterEnemy` пока спавнит своим кодом — см. примечание в конце раздела.
- **Веер** считает `computePelletAngles(baseAngle, pelletCount, spreadRad)`
  (`weapons/pellets.ts`, внутренняя деталь `Weapon`): `spreadRad` — полный угол от крайней левой
  до крайней правой дробинки, при `pelletCount ≤ 1` — одиночный выстрел точно по прицелу.
- **Неточность** — другое понятие: случайный увод всего выстрела внутри конуса `aimSpreadRad`
  (полный угол конуса). Розыгрыш — **один на выстрел** и применяется **до** раскладки веера,
  поэтому дробь одного патрона летит связным конусом. Источник случайности инъецируется в
  конструктор `Weapon` (`Math.random` по умолчанию), поэтому неточность управляема из теста;
  розыгрыш за пределами `[-1, 1]` обрезается и конус за паспортный не расширяет.
- Неточность оружия и `SMART_BOT_AIM_SPREAD` — разные вещи и складываются: первое свойство
  ствола, второе — скилл стрелка (бот промахивается даже идеально точной пушкой).

| Оружие | Глиф | Кулдаун | Урон | Скорость пули | Особенность |
|--------|------|---------|------|---------------|-------------|
| Пистолет | `P` | 250 мс | 1 | 600 px/s | стартовый универсал, точный |
| Дробовик | `S` | 700 мс | 1 × 5 | 600 px/s | веер ~30°, только вплотную |
| Автомат | `A` | 100 мс | 1 | 700 px/s | неточность 0.2 рад — шквал на средней |
| Винтовка | `R` | 900 мс | 3 | 1600 px/s | точная, сносит обычного врага с одного |

**Почему у винтовки нет параметра дальности.** Дистанция полёта пули = `BULLET_SPEED × BULLET_TTL`,
у пистолета это 1200 px при вьюпорте 960×540 — всё оружие уже бьёт дальше, чем видно. Поэтому
«дальнобойность» выражена скоростью пули: 1600 px/s пролетает полэкрана за 0.3 с, и по бегущему
врагу можно целиться в него, а не перед ним.

**Почему автомат неточен.** Патронов и переключения оружия нет — подбор необратим, поэтому
оружие с бóльшим темпом и тем же уроном обесценило бы пистолет навсегда. Урон 1 — уже минимум
при HP врагов 2/3/5, ослаблять темп можно только разбросом. Инвариант в `config.test.ts`
следит, чтобы более быстрое однопульное оружие не било сильнее медленного.

`SmartBot` использует тот же `Weapon` с `WEAPONS.pistol`; враги-стрелки стреляют своим кодом
(`ShooterEnemy.spawnBullet`) и реестра не используют — новое оружие им не достаётся.

### Пикапы оружия (`WeaponPickup`)

Оружие меняется не клавишами, а подбором с пола. Пикап — статическое тело в отдельной
`staticGroup`: квадрат со светлой рамкой, заливкой цветом ствола того оружия, что в нём лежит,
и **глифом** оружия по центру (`WeaponDef.glyph`: `P`, `S`, `A`, `R`). Цвет отвечает
на вопрос «что появится у меня в руках», глиф — «что именно это за пушка»; одного цвета для
второго вопроса не хватает. Уникальность глифов проверяется инвариантом в `config.test.ts` —
иначе два оружия дали бы неразличимые пикапы.

`GameScene` вешает `overlap` игрок↔пикапы → `player.equip(WEAPONS[id])` + `pickup.destroy()`.
Коллизии со стенами нет — пикап статичен и в стену не ставится.

Текстура пикапа генерируется через `DynamicTexture` (а не `Graphics.generateTexture`, как
остальные): глиф — это `Text`, а `Graphics` текст рисовать не умеет. Размер пикапа (32 px) чуть
больше игрока (28 px на экране) — при 26 px глиф был нечитаем.

Патронов в прототипе нет: подобранное оружие остаётся навсегда, пикап расходуется.

### Враги

**Базовый класс `Enemy`:**
- State machine: `IDLE → CHASE → ATTACK / SHOOT / SEARCH`.
- **Тревога**: при агро враг оповещает соседей в радиусе `PACK_ALERT_RADIUS` (событие `packAlert`). Поднимаются только враги в `IDLE` — те, кто ещё не тронулся с места; `SEARCH` и роумящий `SmartBot` (стартует в `PATROL`) тревогу игнорируют.
- **Агро от стрельбы** (`Enemy.aggro`): попадание пули игрока или её пролёт ближе `ENEMY_WHIZZ_RADIUS` переводит врага в CHASE, даже если он игрока не видит. Целью становится **точка выстрела** (`Bullet.firedFromX/Y` — позиция стрелка в момент спавна пули), а не текущая позиция игрока: стрельба из-за угла выдаёт направление, а не самого стрелка. Агро от стрельбы действует только на врагов вне боя (IDLE, PATROL, SEARCH) и, в отличие от визуального обнаружения, **не поднимает тревогу** — промах поднимает одного врага, а не всю комнату. Геометрия «пуля прошла рядом» — чистая `whizzSource()` в `ai/behaviors/alert.ts`; снимок пуль собирает `GameScene.update`.
- **Pathfinding**: `Pathfinder` (Theta* на сетке 64×64 px) строит натянутый any-angle маршрут; если прямая до цели свободна — идёт напрямую без поиска. Путь пересчитывается при отклонении цели > `PATH_RECALC_DIST`.
- Скучивание врагов предотвращают коллизии Arcade Physics (enemy↔enemy collider), отдельной системы позиционирования нет.

**`MeleeEnemy`** (красный):
- IDLE → CHASE при агро. В CHASE — идёт прямо к игроку через pathfinding.
- ATTACK при дистанции ≤ `MELEE_ATTACK_RANGE`: наносит урон с кулдауном.

**`ShooterEnemy`** (синий):
- IDLE → CHASE при LoS + агро-дистанции. В CHASE — навигация к позиции игрока.
- SHOOT при LoS в зоне `SHOOTER_RANGE`: стреляет с кулдауном 1500 мс, кайтит через `kiteAction()` — отступает ближе `SHOOTER_KITE_RETREAT_DIST`, сближается дальше `SHOOTER_KITE_ADVANCE_DIST`, в зоне комфорта между ними стрейфит.
- SEARCH при потере LoS: идёт к последней известной позиции игрока.
- LoS кешируется один раз за тик (`losCache`).

**`SmartBot`** (зелёный) — соперник **уровня игрока** с продвинутым ИИ в духе ботов Quake 3:
- Характеристики как у игрока: HP 5, скорость 200, то же оружие (`WEAPONS.pistol`: кулдаун 250 мс,
  скорость пули 600), стреляет в группу `enemyBullets`. Оружие не меняет — пикапы для игрока.
- Состояния: `PATROL → CHASE → SHOOT → SEARCH → PATROL` (поверх общего `EnemyState`), плюс
  отдельный режим отхода в укрытие, перекрывающий автомат.
- **Роуминг** (`PATROL`, стартовое состояние): бот не простаивает, а ходит по карте —
  идёт к случайной проходимой точке (`Pathfinder.randomWalkableWorld`, дистанция ≥
  `SMART_BOT_PATROL_MIN_DIST`), по достижении выбирает новую. При обнаружении игрока
  (LoS + `SMART_BOT_AGGRO_RANGE`) → `CHASE`.
- **Упреждающий прицел**: целится в экстраполированную позицию игрока (`pos + velocity·dist/bulletSpeed`).
  Модель «честности»: задержка реакции `SMART_BOT_REACTION_MS` перед открытием огня + случайный
  разброс `SMART_BOT_AIM_SPREAD` на каждый выстрел (поворот корпуса — без разброса). Задержка
  реакции взводится один раз на завязку боя: короткое мигание LoS (короче `SMART_BOT_LOS_GRACE_MS`)
  её не перевзводит, поэтому в устоявшемся бою темп стрельбы = кулдаун оружия (как у игрока).
- **Уклонение**: сканирует `playerBullets`; при летящей в него пуле (близко + малое боковое
  отклонение) делает рывок перпендикулярно её курсу на `SMART_BOT_DODGE_DURATION`, перебивая маневр.
- **Кайтинг**: удержание дистанции (отступает ближе `SMART_BOT_KITE_RETREAT_DIST`,
  сближается дальше `SMART_BOT_KITE_ADVANCE_DIST`) + стрейф со сменой стороны.
- **Тактика укрытий**: при HP ≤ `SMART_BOT_LOW_HP` ищет ближайшую проходимую точку без LoS к игроку
  (`Pathfinder` + геометрия стен) и уходит туда, не стреляя; затем возвращается в бой. Лечения в
  прототипе нет, поэтому отход однократный с кулдауном `SMART_BOT_RETREAT_COOLDOWN_MS`.
- **Поиск** (`SEARCH`, потеря LoS): идёт к последней известной позиции (`lastKnownPos`); дойдя,
  не замирает, а обыскивает район `SMART_BOT_SEARCH_DURATION` мс — ходит по случайным проходимым
  точкам в радиусе `SMART_BOT_SEARCH_RADIUS`. Вернулась LoS → бой; по таймауту → роуминг.
- Спавн через объект `smart` в Tiled-слое `spawns`; попадает в общий `enemyGroup`.

### Уровни

Уровни рисуются в Tiled и экспортируются в `public/assets/maps/<key>.json`; реестр — `level/levels.ts`.
`LevelLoader.loadTiledLevel` читает три слоя:
- `floor` — только визуал;
- `walls` — все выставленные тайлы солидны; из них же собираются `WallDef[]` для LoS и pathfinding;
- `spawns` — точечные объекты, идентификатор берётся из `type` (или `name`):
  `player_start`, `melee`, `shooter`, `smart`, `weapon_pickup`.

У объекта `weapon_pickup` оружие задаётся пользовательским свойством `weapon` — любой id из
реестра (`pistol`, `shotgun`, `automat`, `rifle`). Чистые функции разбора — в `level/spawns.ts`:
`classifySpawn` (идентификатор → тип спавна) и `readPickupWeaponId` (свойства объекта → id оружия).
Неизвестное или отсутствующее оружие пикапа логируется предупреждением и пропускается — битые
данные карты не валят загрузку уровня.

Неизвестный **идентификатор спавна** логируется предупреждением с идентификатором, координатами и
списком допустимых значений (`KNOWN_SPAWN_IDS` из `level/spawns.ts`), после чего объект
пропускается — опечатка в Class видна в консоли, а не только по отсутствию врага в бою.

Существующие карты:

| Ключ | Размер | Содержимое |
|------|--------|------------|
| `level1` | 1920×1088 | боевая карта: 1 melee-враг, два блока стен, три пикапа (дробовик, автомат, винтовка) рядом в центре |
| `level2` | 640×640 | три shooter-врага, блок стен 2×2 в центре, мёртвый спавн `ranged`; карта целиком влезает в вьюпорт |
| `level3` | 640×640 | дуэль с `SmartBot` один на один, та же геометрия, что у `level2` |

Карты `level2` и `level3` (640×640) меньше вьюпорта 960×540 по ширине, поэтому камере некуда
следовать — уровень виден целиком. Дистанции ощущаются только на `level1`.

### GameScene — точки интеграции

- Две группы пуль: `playerBullets` и `enemyBullets` (разделение упрощает collision rules).
- Коллизии: пули↔стены (уничтожение), playerBullets↔враги (урон), enemyBullets↔игрок (урон), игрок↔стены, враги↔стены.
- Overlap игрок↔`pickups` (статическая группа) → смена оружия и уничтожение пикапа.
- Тик AI каждого врага вызывается в `update()`.
- Тревогу разносит подписка `GameScene` на событие `packAlert`: враг эмитит свои координаты, сцена переводит соседей в `CHASE`.
- При 0 живых врагов → GameOver (WIN). При смерти игрока → GameOver (LOSE). В GameOver уходит и конфиг уровня — для кнопки «Заново».
- События `scene.events`, на которые подписываются оверлеи: `hpChanged` (эмитит `Player.takeDamage`), `weaponChanged` (`Player.equip`, отдаёт имя оружия), `enemiesChanged` (`GameScene.update`, только при изменении числа живых), `playerDied`, `enemyDied`, `packAlert`.
