# Pathfinding & Debug Guide

## Как включить debug-режим

Нажать **F1** во время игры — появятся линии маршрутов и кресты слотов.
Повторное **F1** — скрыть.

---

## Debug-оверлей (верхний левый угол)

```
HP:     5 / 5       — здоровье игрока
Враги:  6           — количество живых врагов
Pos:    200, 200    — позиция игрока в мировых координатах (px)
Vel:    0, 0        — скорость игрока (px/сек)
FPS:    60          — частота кадров
F1: debug paths     — подсказка переключения визуализации
E0: IDLE            — состояние каждого врага
E1: CHASE
...
```

### Состояния врагов

| Состояние | Что происходит |
|-----------|----------------|
| `IDLE`    | Враг стоит, игрока ещё не заметил |
| `PATROL`  | Роуминг по карте — стартовое состояние `SmartBot` |
| `CHASE`   | Движется по A*-маршруту к игроку или к последней известной точке |
| `ATTACK`  | MeleeEnemy в зоне атаки, наносит урон с кулдауном |
| `SHOOT`   | Стреляет с прямой видимостью, одновременно кайтя дистанцию |
| `SEARCH`  | Игрок потерян. Стрелок идёт к `lastKnownPos`, melee уже дошёл и ждёт у неё |

Стрейфа и уклонения в таблице нет намеренно: это действия внутри `SHOOT`, а не состояния —
в `EnemyState` их не ищите.

## Линии маршрутов (F1)

- **Красная линия** — маршрут MeleeEnemy от его текущей позиции по вейпоинтам A* до целевого слота
- **Синяя линия** — маршрут ShooterEnemy (аналогично)
- **Жёлтый крест `+`** — целевая позиция слота (куда враг хочет прийти)

Линия **есть** → враг в CHASE и pathfinder нашёл путь через клетки сетки.  
Линии **нет** → враг IDLE / уже в слоте / путь не найден (тогда двигается напрямую).

## Как проверить, что всё работает правильно

**Нормальное поведение:**

1. Все `E0`–`E5` = `IDLE` пока игрок далеко
2. При подходе игрока < 250 px: ближайший враг переходит в `CHASE`, соседние в радиусе 300 px тоже агрятся (pack alert) — можно видеть несколько врагов разом
3. После F1: красные/синие линии **огибают стены** — идут ломаной через свободные ячейки, а не насквозь через препятствие
4. Жёлтые кресты разведены по разным сторонам от игрока — слоты распределены равномерно (8 слотов по 45°)
5. MeleeEnemy (`E*: ATTACK`) снижает HP игрока
6. ShooterEnemy (`E*: SHOOT`) стреляет и кайтит дистанцию; при потере LoS — `SEARCH`

**Признаки проблем:**

| Симптом | Причина | Что проверить |
|---------|---------|---------------|
| Линия идёт сквозь стену | A* не обходит стену | Уменьшить `PATH_CELL_SIZE` (< 64 px) |
| Враг в `CHASE`, но не движется | Застрял у вейпоинта | Увеличить `WAYPOINT_REACH_DIST` |
| Все враги агрятся при старте | Слишком большой радиус | Уменьшить `ENEMY_AGGRO_RANGE` |
| HP не снижается | MeleeEnemy не достигает цели | Проверить `MELEE_ATTACK_RANGE` и `MELEE_SLOT_RADIUS` |
| ShooterEnemy не стреляет | Нет LoS / враг не доходит | Проверить `SHOOTER_RANGE` и стены |

## Константы патфайндинга (`src/config.ts`)

| Константа | Значение | Смысл |
|-----------|----------|-------|
| `PATH_CELL_SIZE` | 64 px | Размер ячейки A*-сетки (меньше = точнее, медленнее) |
| `PATH_RECALC_DIST` | 128 px | Пересчёт пути если цель сместилась дальше этого значения |
| `WAYPOINT_REACH_DIST` | 24 px | Расстояние, при котором вейпоинт считается достигнутым |
| `ENEMY_AGGRO_RANGE` | 250 px | Радиус обнаружения игрока |
| `PACK_ALERT_RADIUS` | 300 px | Радиус оповещения соседних врагов |

## Как устроен A*

Карта 1920×1080 px разбита на сетку 30×17 = 510 ячеек (64 px каждая).  
При инициализации уровня каждая ячейка, перекрывающая стену (+ отступ 32 px), помечается непроходимой.

При вызове `moveAlongPath()`:
1. Если цель сместилась больше чем на 128 px — путь пересчитывается
2. A* строит путь по 8-направленной сетке (включая диагонали, стоимость √2)
3. Возвращает список вейпоинтов; последний вейпоинт = точная позиция слота
4. Враг движется к текущему вейпоинту; при достижении (< 24 px) берёт следующий
