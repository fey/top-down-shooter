# Оружие — записи реестра, а не подклассы

`WEAPONS` в `config.ts` хранит `WeaponDef` (темп, урон, скорость пули, веер, неточность,
геометрия ствола-индикатора, глиф), единственный класс `Weapon` их исполняет. Новая пушка — одна
запись; ни нового файла, ни наследника.

Очевидный ООП-путь — базовый `Weapon` и наследник на каждый ствол — здесь ничего не даёт:
оружие в прототипе различается только числами, поведение у всех одно (кулдаун → веер → неточность
→ спавн пуль). Подклассы размазали бы числа баланса по четырём файлам, тогда как правило проекта —
держать их в `config.ts`, и потребовали бы `instanceof` там, где сейчас достаточно прочитать поле.
Дополнительно реестр даёт то, чего иерархия не даёт даром: инварианты проверяются тестом на весь
набор сразу (`config.test.ts` — уникальность глифов, положительность чисел), а текстуры игрока
и пикапа генерируются циклом по реестру.

Та же форма распространяется на врагов задачей `top-down-shooter-stz`: реестр `ENEMIES` вместо
россыпи констант с префиксом и опознания вида через `instanceof`.

## Граница

Реестр держит различия в числах и внешнем виде. Оружие, которому нужно другое **поведение**
(рикошет, снаряд с задержкой, луч вместо пули), в `WeaponDef` не описывается — это повод
пересмотреть решение, а не растить дескриптор флагами.
